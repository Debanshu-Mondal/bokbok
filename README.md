# bokbok

A tiny 1:1 direct-message chat app with a retro pixel "coop" theme. Real-time
messaging over Socket.io, JWT auth, and procedurally generated pixel avatars
(no photo upload needed — everyone gets a unique little pixel identity based
on their username).

- **Backend**: Node, Express, Prisma (PostgreSQL), Socket.io, JWT auth
- **Frontend**: React (Vite), react-router, socket.io-client

## Project layout

```
backend/    Express API + Socket.io server, Prisma schema
frontend/   React app (Vite)
render.yaml Render Blueprint for one-click deploy
```

In production, the backend serves the built frontend as static files from
the same origin (`frontend/dist`), so the whole app is one deployable web
service.

## Local development

You'll need a PostgreSQL database (a free one from
[Neon](https://neon.tech), [Supabase](https://supabase.com), or a local
Postgres instance all work).

```bash
# backend
cd backend
cp .env.example .env   # fill in DATABASE_URL and JWT_SECRET
npm install
npx prisma db push     # creates the tables
npm run dev             # http://localhost:3000

# frontend, in a second terminal
cd frontend
npm install
npm run dev              # http://localhost:5173
```

The Vite dev server proxies `/api` and `/socket.io` to `http://localhost:3000`
(see `frontend/vite.config.js`), so just open the frontend URL.

## Deploying to Render

This repo includes a `render.yaml` Blueprint that provisions:

- one **Web Service** (`bokbok`) — builds the frontend, then runs the Express
  server, which serves the built frontend and the API/sockets from the same
  origin
- one free **PostgreSQL** database (`bokbok-db`), wired up automatically via
  `DATABASE_URL`

### Steps

1. Push this repo to GitHub (or GitLab/Bitbucket).
2. In the Render dashboard, choose **New > Blueprint** and point it at the
   repo. Render will read `render.yaml` and create both resources.
3. On first boot, the start script runs `prisma db push`, which creates the
   `User` and `Message` tables on the fresh database — no manual migration
   step needed.
4. Once deployed, Render gives you a URL like
   `https://bokbok-xxxx.onrender.com`. Open the service's **Environment**
   tab and set `CLIENT_URL` to that exact URL (the placeholder in
   `render.yaml` won't match your generated subdomain). This isn't strictly
   required for the app to work — the frontend is served same-origin — but
   it keeps the CORS/Socket.io config accurate if you ever split the
   frontend out to its own static site later.

`JWT_SECRET` is auto-generated by Render; you don't need to set it yourself.

### Manual setup (without the Blueprint)

If you'd rather configure things by hand: create a Web Service from this
repo with build command `npm run build` and start command `npm run start`,
add a Postgres database, and set `DATABASE_URL`, `JWT_SECRET`, and
`NODE_ENV=production` as environment variables on the service.
